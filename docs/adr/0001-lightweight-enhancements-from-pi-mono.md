# 1. pi-coding-agent からの軽量な機能強化

日付: 2026-03-12
更新日: 2026-03-12

## ステータス
承認 (Accepted)

## コンテキスト
`my-agent-core` は、オリジナルの `pi-coding-agent` (badlogic/pi-mono) が提唱する「超シンプル」なエージェント・コアの概念を忠実に再現した軽量な Python 実装です。現在は `read`, `write`, `edit`, `bash` の 4 つの基礎ツールと、Markdown ファイルを用いたコンテキスト注入の仕組みを持っています。

この「軽量さ・シンプルさ」を損なうことなく、実用性やUX、推論の堅牢性を高めるために、オリジナルの `pi-coding-agent` からいくつかの機能を取り入れる必要があります。しかし、TypeScript 版の持つ複雑な拡張モジュール機構や依存パッケージ（`diff` など）をそのまま持ち込むことは設計思想に反します。

## 決定事項

Python のコアモジュールや既存の枠組みで実装可能な範囲として、以下の機能を採用します。

### ADR 当初の 5 提案（再評価後）

1. **オンデマンド・スキル (On-demand Skills)**
   * システムプロンプトのガイドラインに組み込み（独立実装不要）。
   * `.agent/skills/*.md` などのファイルを `read` ツールで読み込む方針を明示。

2. **コンテキスト情報の階層的ロード (Hierarchical Context)**
   * グローバル（`~/.config/my-agent-core/AGENTS.md` または `~/.agents/AGENTS.md`）を
     プロジェクトローカル（`cwd/AGENTS.md`）より先に読み込んで結合。

3. **インライン・ファイル注入 (`@file` シンタックス)**
   * ユーザー入力の `@ファイル名` を、プロンプト送信前に自動でそのファイル内容で展開・置換する。

4. **コンテキスト付きの「外科的編集」 (Context-aware Edit)**
   * `edit` ツールに `occurrence_index`（1-based）パラメータを追加。
   * 重複マッチ時にインデックス指定で対象を特定可能にする（`diff` 依存なし）。

5. **「プラン先行」のガイドライン強化 (Plan-first Guidelines)**
   * 「複雑なタスクでは最初に `plan.md` を作成する」指示をシステムプロンプトに追加。

### ADR への追加項目（pi-agent-core 実装詳細の調査から判明）

6. **リトライロジック (Retry Logic)**
   * `llm.py` の `LLMClient.stream()` に指数バックオフ自動リトライを追加。
   * 対象: HTTP 429 (Rate Limit) / 5xx (Server Error) / `httpx.TransportError`
   * 最大 3 回、遅延 1s → 2s → 4s。新規依存パッケージなし。

7. **コンテキストウィンドウ管理 (Context Window Management)**
   * `loop.py` にスライディングウィンドウ実装（`_trim_messages`）を追加。
   * デフォルト上限: system を除く 40 メッセージ。ターン境界（user 先頭）でトリミング。

### 取り込まない機能

以下は CLI・シンプルさの観点からスコープ外とする。

- フルイベントシステム (agent_start/end, turn_start/end など) — CLI には過剰
- Agent クラスラッパー — 現在の直接ループで十分
- ThinkingLevel 設定 — `MODEL` 環境変数で代替
- コスト追跡 — シンプルさを優先
- マルチエージェント / 拡張システム — スコープ外

## 影響 (Consequences)

### ポジティブ
* **信頼性の向上**: リトライにより、一時的な API レート制限やネットワーク障害で会話が中断しなくなる。
* **長期セッションの安定化**: コンテキストウィンドウ管理により、長い会話でのトークン溢れを防止。
* **トークン効率の向上**: オンデマンド・スキルにより初回のコンテキスト枠を節約でき、会話履歴を長く維持できる。
* **UX の向上**: インラインファイル注入により、目的のファイルをエージェントに伝える際の手間（ツール呼び出し待ち）が不要になる。
* **編集の堅牢化**: `occurrence_index` により、同じ文字列が複数回出現するテンプレート等の編集ミスが減少する。
* **全般的な汎用性**: 階層的コンテキストにより、ユーザーごとの共通設定（言語設定や型の好みなど）を全プロジェクトに容易に適用できる。

### ネガティブ
* `llm.py` にリトライロジックが加わり、若干複雑化する。
* `loop.py` または `server.py` 内に、インライン展開用の正規表現サーチや、階層ファイルの読み込み処理など、若干のロジック追加が発生する。
* `tools.py` の `edit` ツールの実装がわずかに複雑化する。
* コンテキストウィンドウ管理によって古いメッセージが失われるため、非常に長い会話では文脈が途切れる可能性がある。
